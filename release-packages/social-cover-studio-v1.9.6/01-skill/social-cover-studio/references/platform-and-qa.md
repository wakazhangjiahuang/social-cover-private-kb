# 三平台规则与成品 QA

## 规则适用原则

1. 先确定 A 抖音 / B 微信视频号 / C 小红书，再读取对应 `platform-modes/*.md`。
2. 官方规则、平台团队论文、实际发布器 UI、GitHub 实现记录和第三方经验分层记录；不能把 GitHub 经验写成官方规则。
3. 每次涉及近期规则、尺寸、AI 标识、商业推广时按需联网刷新，记录核验日期与版本。
4. 不声称知道平台未公开的固定权重、固定流量池、统一 CTR 门槛或必爆公式。
5. 公众号（WeChat Official Accounts）与微信视频号（WeChat Channels）严格区分；B 模式只使用视频号规则。

## 平台硬门禁

- `A` 抖音：区分上传封面、视频首帧、开场段；按实际入口核对比例；真实视频/实测证据；AI 生成内容主动标识；封面承诺与视频内容一致。
- `B` 视频号：好友推荐与算法推荐双入口意识；区分竖版/横版发布封面；在可用时检查社交分享预览；不伪造好友背书或互动；AI 内容标识。
- `C` 小红书：区分推荐与搜索；笔记首图/视频封面分开判断；商品/商家专项规则只在适用范围执行；标题、封面和正文一致；AI 内容标识。

## 设计与营销检查

- 主视觉锚点在手机缩略图可辨；标题准确、断行自然；无乱码、漏字、错字或被裁切。
- 主体、人脸、产品关键细节、真实 UI 和数据不被遮挡。
- 视觉层级、网格、字体、色彩、留白和信息密度符合本平台入口。
- 封面承诺必须由视频/笔记正文兑现；无虚构结果、排名、客户、评价、功效、价格或 ROI。
- 参考图只迁移抽象视觉 DNA，不复制第三方身份、Logo、文案、IP 或受保护的独特表达。
- 系列封面保持品牌识别但避免结构同质化；6→3 的差异须是实质差异。

## 画幅与文件检查

- 比例由当前平台发布器/封面槽、用户指定和实际内容方向共同决定。
- 视频画布比例与封面图比例不是同一个字段。
- 不把某个 GitHub 项目的默认 1080×1440 或 3:4 说成平台官方唯一规格。
- 多张成品逐张核对尺寸、格式、色彩模式、清晰度和独立文件；不以合集替代。

## 数据与实验

- 发布前只报告策略、设计和合规 QA；不预测真实 CTR。
- 发布后使用平台后台原始字段和定义。没有点击事件及对应曝光分母时不计算 CTR。
- 先后发布的不同笔记/视频只能作为观察性对照；随机分流/平台受控实验才称为 A/B。
- 归因时考虑内容主题、发布时间、受众、流量来源、投放、视频开场和正文质量等混杂因素。

## 验收状态

逐项标记 `PASS / FAIL / BLOCKED / NOT_RUN`。模型自评不能替代独立设计盲评、真实平台后台数据或可复现文件检查。未做真实发布/实测时不得标为已验证。
