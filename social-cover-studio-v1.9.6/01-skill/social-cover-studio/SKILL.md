# 自媒体封面设计工作室｜三平台独立策略引擎

**版本：1.9.6｜平台：A 抖音 / B 微信视频号 / C 小红书**

## 1. 定位与任务边界

本 Skill 是封面策略、视觉设计、图片生产与验收系统，不是通用模板或自动发布工具。支持：新建/重设计、系列封面、仅标题、参考图分析、原稿修复、发布后复盘。纯正文、纯口播、视频剪辑、自动发布及无关 Skill 开发不在职责内。

先识别任务，再判断是否需要平台。仅分析、仅标题、原稿修复、复盘不得因缺少平台而自动阻断；只有平台会实质改变创作策略时才要求选择平台。明确多平台才联合执行，各平台独立生成 Brief、标题、结构、画幅、成品和 QA，不得只缩放同一张图。

## 2. 任务路由与默认行为

| 任务 | 必须执行 | 禁止越界 |
|---|---|---|
| 新建/参考重设计/系列封面 | 受众与点击价值判断、结构、标题压缩、视觉生产、逐张验收 | 未授权不扩展平台或数量 |
| 仅标题文案 | 事实核验、受众任务识别、点击理由提炼、自动选定、字符门禁 | 不出图、不要求用户从候选中自行挑选 |
| 仅分析/参考图拆解 | 逐图观察、DNA、冲突与适用建议 | 不自动转成创作 |
| 原稿修复 | 按原稿、保留项和用户数量修复 | 不擅自加标题、营销元素或套用6→3 |
| 发布后复盘 | 读取真实后台数据、口径、窗口和混杂因素 | 无数据不推测CTR或因果效果 |

用户指定数量、平台、比例、尺寸、格式、保留项和禁止项优先。创作默认每个平台3张独立成品；仅当用户未指定数量且任务适合多方向方案时，内部规划6个有实质差异方向并由AI自动择优3个。默认数量不覆盖原稿修复或单图任务。除用户明确要求外，不把多个候选交给用户代替专业判断。

## 3. 三个平台独立策略

- **A｜抖音**：分别判断推荐、搜索、主页/分享场景；区分视频封面、视频首帧和开场段。
- **B｜微信视频号**：考虑好友推荐与算法推荐并行；区分视频画幅、封面槽、主页和分享预览；不得套用公众号规则。
- **C｜小红书**：区分推荐与主动搜索；按搜索意图、笔记内容、首图识别、收藏/决策场景设计。

三平台适配器分别决定入口、内容消费方式、标题字段、封面/首帧关系、画幅裁切、CTA、数据指标与合规检查。公开算法机制不等于完整权重；禁止编造流量池、首轮曝光、完播阈值、CES权重或CTR保证。

## 4. 双层输入变量

### 第一层｜内容类型 × 点击/观看动机 × 营销目的

三轴独立选择，允许 AUTO；明确指定标记 `user_locked`，自动判断标记 `inferred`。
- 内容类型：干货知识、教程步骤、痛点解决、案例成果、观点判断、测评比较、产品种草、经验记录、生活叙事、审美灵感、作品集、活动/新品、FAQ等。
- 主点击/观看动机：痛点、好奇、知识价值、结果证明、情绪共鸣、利益诉求、收藏价值、比较决策、信任建立等。只选一个主驱动，最多一个辅助动机。
- 营销目的：认知触达、兴趣种草、获客、产品推广、信任验证、案例展示、系列传播、咨询/购买转化等。
- 同步记录目标受众、内容承诺、证据引用和CTA边界。内容类型、用户动机和商业目的不得互相替代。

### 第二层｜信息结构 × 视觉风格 × 主视觉路线

三项独立选择，允许 AUTO：
- 信息结构：保留 L01–L17，按内容与受众选择；不适配时允许原创结构。
- 视觉风格：使用现有风格ID或用户上传参考DNA；锁定风格内做差异，不强制换风格。
- 主视觉路线：人物、产品、作品/插画、UI、图解、文字、真实场景等。

17类信息结构、18款视觉风格、64款构图、8种几何家族、平台A/B/C及C01–C18组件属于不同维度，禁止混用编号。64款只作构图候选；不得把图库合成图当作真实案例或实拍证据。

## 5. 素材与参考图合同

先区分参考封面、基础样式图、主体/保真素材、品牌资产、平台截图。每张参考图记录用途（构图/风格/基础版式/保真素材，可多选）、保留项、可修改项、禁止项；未填写时先提取可迁移DNA，不强制问卷。

逐图分析网格、构图、视觉锚点、标题层级、字体特征、色彩角色、主体裁切、背景/笔触、装饰、留白、品牌识别及缩略图表现。结论标记 `OBSERVED`（直接可见）、`INFERRED`（推断）、`UNKNOWN`（图像不能证明）。字体具体名称、权属、CTR、真实身份等不能从图像直接证明时保持 UNKNOWN。

保真素材与风格参考分开处理。保真素材优先保持原始形态、比例、角色、笔触、色彩与构图；风格参考只迁移抽象设计规律。未经授权不复制第三方作品、角色、肖像、Logo、文案或独特商业资产。

## 6. 固定知识资产与来源

先运行 `python tools/check_package.py` 检查必需文件；缺失或哈希变化时阻断相应依赖步骤。再读取 `assets/knowledge-locator.json`，核对固定 Manifest、提交 ref 和哈希，再按本轮需要读取选中索引与记录；禁止全仓扫描、浮动 main 回退和无关资料堆砌。使用 `scripts/cover_assets.py`：`validate` 检查本地索引，`verify-remote` 校验固定远端 Manifest；`query/style/joint` 选择候选；`fetch --kind layout|style --id ID --asset image|thumbnail|preset --destination DIR` 下载选中资产并核对 Manifest 及 SHA256。

标题/钩子历史候选使用 `record --kind title|hook --platform A|B|C --surface cover_main_title|cover_subtitle|platform_title --industry ID`，可按 `--motive` 与 `--evidence` 限定。平台适用性未知默认排除；仅构思阶段可显式 `--include-unverified`，必须保留 `REQUIRES_TASK_REVIEW` 并在实例化后重新过门禁。450条规则派生元数据不等于450条已获人工/平台认证。

**封面文案知识优先级：** 封面创作/标题优化前，必须先读取本地 `references/cover-copy-v6.md`。该文件是当前最高优先级规则，并与 `assets/knowledge-locator.json` 固定的 GitHub 知识快照对应。若文件缺失或哈希不匹配，标记 `BLOCKED`，不得退回V5/V4或旧候选库充当当前规则。随后读取 `references/cover-value-method.md` 与 `references/title-review.md`（四层表达、用户视角、点击动机、公式化检查、主副互补、字符和视觉验证）；插画实例按需读 `references/title-case-atlas.json`。温泉/文旅创作者邀约另读 `references/partner-invitation.md` 与 `references/hot-spring-positive-cases-v2.json`，其四张原始PNG已核对哈希并记录精确字符；该JSON记录不等于图片已打包或营销效果已验证。插画封面任务另读 `references/illustration-note-alignment-v1.json`：它包含三平台18篇脚本的封面、锁定开场、正文、Calling、发布文案及108条拍摄证据提示，用来核对标题承诺是否由正文/画面兑现。

V5及更早规则只作历史版本，不得覆盖V6。旧225条标题、225条钩子、10组公式仅是历史候选，默认不调用；用户明确要求参考时也必须重新按V6审核。知识库不可访问时标记 BLOCKED/UNKNOWN，只阻断依赖该资产的步骤，不阻断可独立完成的工作。保留原18模块/179字段兼容边界、17结构、18风格、64构图、现有品牌适配器和平台来源登记，不得重命名或伪造原始字段。

## 7. 封面主副标题工作流

默认只创作封面图片主标题与副标题；只核对已有开场与正文的兑现，不主动扩展为发布文字、笔记正文、话题或口播。插画任务优先按对应平台和内容ID读取18篇对照样例；样例中的0–3秒、3–8秒、正文、Calling和发布文案只作为对照材料，用户只要求优化封面时一律不得改写这些字段。

**内部分析与封面成品严格分离。** 目标受众、共同任务、痛点、需求、利益、观看收益、钩子名称、公式、评分、证据门禁及“四项工作指导”只用于内部策划，不得把这些标签或分析句直接排进封面、公司简介、网站介绍、宣传正文或其他成品。四项工作指导是执行方法，不是内容主题、公司介绍目录或网页栏目；只有用户明确要求撰写相关介绍时，才按真实业务资料另行处理。

“关我什么事”是内部审稿问题，不是要求封面机械出现“你/我/关我什么事”。必须先判断目标受众正在完成的任务、卡点、替代方案与当前决策，再提炼对其有用的具体交付。不得把“内容价值、提升审美、商业机会、参与共创、干货分享”等抽象词本身当成观看收益；必须说明受众看完能获得什么具体判断、可用资料、方法、选择依据、审美识别或参与机会。

### 7.1 受众需求与点击理由的内部决策

按 `references/cover-value-method.md` 执行：
1. 识别一个主要受众的共同任务；不同岗位若任务相同可合并，任务/利益/决策不同则拆分。
2. 写清观众正在做什么、卡在哪里、想得到什么进展及当前替代办法。
3. 完成四层内部映射：目标客户利益→营销钩子→事件和关键词→证据补充；四层不是四行文案，也不要求全部写进封面。
4. 允许商业结果、审美学习、图鉴整理、市场情报、选型判断、人物故事、地方叙事等成为价值，不强制把每条写成赚钱利益句。
5. 明确唯一主点击理由和一个由正文/画面兑现的继续观看问题；判断用户视角、钩子是否自然、主副是否互补。
6. 内部比较2–3条不同价值路径（不是同义标题），按用户任务、价值识别、点击动机、自然表达、证据兑现和主副画面协同，由AI自动选定一条。
7. 先保证表达准确，再压缩；默认只交付一个最终标题组合，不让小白用户替AI做专业筛选。只有用户明确要求多方案时才展示备选。

点击理由必须同时回答：谁会在意、他能获得什么、为什么这条内容值得现在点开、现有材料如何兑现。任一答案模糊，退回价值判断，不靠增加感叹号、冲突词、问号或“你/我”补救。

### 7.2 主副标题、四层表达与主画面优先

默认按9:16图片型封面执行，具体平台/入口规格另行覆盖：
- 主标题默认最多15个汉字；副标题最多18个可见字素簇。英文、数字、空格、标点、Emoji另计可见字素簇和实际字宽；换行不计。
- 主标题允许1–3行，副标题允许1–2行。不得为了满足单行而删掉关键语义；也不得为了保留长句而缩小字号到不可读。
- 地点/品牌/系列标签、中间邀约牌和CTA是独立字段，不并入主副标题总字符预算；CTA仍须明确授权。所有文字需整体检查视觉拥挤。
- 不设跨所有封面通用的主视觉60%、文字22%或副标题55%等硬面积比例。人物、商品、图鉴、真实场景、透明叠字素材和信息图的构图任务不同；以完整成图的第一注意力、文字可读性、缩略图和分享裁切判断。
- 透明文字叠加素材不含完整主画面；在与真实/原创背景合成前，主视觉门禁记NOT_APPLICABLE，不得宣称完整封面视觉通过。
- 主标题建立对象/兴趣/结果/选择/风格/人物等入口；副标题补主要理解缺口，可补证据、情绪、方法、开发路径或适用场景。没有新增理解或期待时允许省略。
- 先保证用户视角、点击动机、表达自然、主副互补和事实兑现，再做字符压缩。禁止机械套用利益句、冲突句、疑问句或感叹号。
- 主画面展示本内容最值得看的作品、商品、角色、场景、资料或差异；文字辅助，不让分析说明包办全部信息。用户明确要求文字海报/信息图时另行判断。

执行 `python tools/cover_title_gate.py --main "..." --subtitle "..."` 检查主标题汉字数、副标题可见字符、行数和CTA授权；透明叠字用 `--mode overlay`，纯文案用 `--mode text-led`，完整封面需另做视觉审查。字符检查不能替代语义、缩略图或营销效果验证。

### 7.3 硬门禁、自动返工与交付

硬门禁：`facts`、`audience_mirror`、`click_reason`、`pair_complementarity`、`fulfillment`、`text_budget`、`scope_and_rights`；完整封面另执行 `visual_dominance`。纯文本任务视觉记NOT_RUN；透明叠字素材在完整合成前记NOT_APPLICABLE。任一FAIL不得排名；UNKNOWN/NOT_RUN/BLOCKED或缺来源引用返回HOLD。

AI必须先自检、自动压缩并最多进行两轮定向返工；仍不通过时说明具体阻断原因，只询问一个不可替代的必要信息。不得把多轮人工修改当成默认工作流。

新量表与执行器为 `config/cover-rubric.json`、`tools/cover_review.py`：100分试行权重20/20/20/10/10/10/5/5，分别评估用户视角、价值可识别、点击动机、事件关键词、证据兑现、主副画面互补、自然精确表达与缩略图层级；85分以上仅为编辑高分候选，且D1/D2/D3/D6须达到3分、全部维度不低于2分。纯文本最高95分，不把未执行的视觉维度换算成满分。分数只用于内部定位问题，不证明真实受众接受或营销效果。

## 8. 视觉生产与导出

优先真实场景、真实人物、工作过程、产品、系统界面和作品素材；专业知识内容可使用帖子、文档卡、图解或白边版式。AI概念场景不得冒充实拍、真实客户或实际交付。

图像生成与精确排字/导出分离。锁定文案使用确定性文字层；不能保证准确排字时先生成无字底图，再用排版工具添加文字。实际导出后读取文件验证解码、尺寸、比例、格式、数量和哈希，不信任Prompt或模型自报尺寸。

默认规格9:16、1440×2560 px、PNG；平台当前发布入口、用户明确要求或真实素材规格另有要求时，以已核实入口/用户要求为准，并记录实际规格。比例按整数交叉相乘精确验证；禁止无声明拉伸、裁掉锁定文字或改变原稿风格来凑尺寸。

## 9. 约束条件与禁止项

- 严格遵循用户指定任务模式、平台、数量及交付范围；多平台明确多选才联合执行。
- 区分视频封面、视频首帧、图文首图及分享预览，不混用规则；平台规格以当前官方规则和实际发布入口为准。
- 标题、图片、卖点必须与本轮真实内容和原始资料一致；禁止虚构案例、客户、数据、评价、排名、资质、功能及效果。
- 未证实信息标记 UNKNOWN/待确认；不擅自修改品牌名、产品信息、关键数字及业务事实。
- 主体明确、信息层级清晰、构图完整、文字可读；禁止错字、漏字、乱码、伪汉字、主体错误裁切、比例失衡和无效留白。
- 系列保持品牌识别，但每张主题和视觉结构须有实质差异；禁止机械套版。
- 每张封面独立生成、独立保存、独立交付；禁止九宫格、拼图、合集及多张封面合并输出。
- 创作任务必须实际生成成品，不得以方案或示意图代替；最终ZIP不得缺图、重复、损坏或混入无关文件。
- 创作交付前运行 `tools/check_image_export.py FILES --width W --height H --count N --write-zip OUTPUT.zip --require-zip`；已有ZIP用 `--zip`。文件验收不代替视觉或平台验收。

## 10. 四层验收与状态

1. **平台层**：模式、入口、适用规则、AI标识、画幅、安全区。
2. **设计层**：层级、网格、字体、色彩、主体、缩略图、裁切、系列差异、主视觉与文字面积预算。
3. **营销层**：标题、封面、正文、证据、CTA一致；声明逐项有据。
4. **数据层**：只用平台后台原始字段与定义；无点击和对应曝光分母不计算CTR；非随机/受控分流不称严格A/B。

分开记录结构通过、语义通过、文件通过、视觉通过、平台预览通过、发布后效果。离线成品合格不等于平台预览通过；平台预览通过不等于已发布或营销有效。FAIL/UNKNOWN/NOT_RUN不能被总分覆盖。相关检查状态必须附方法、对象、证据位置和版本。

## 11. 输出合同

- 诊断：任务模式、平台（适用时）、关键问题、证据、风险和必要修改项。
