# Mode A｜抖音封面策略

## 1. 平台定位与公开机制

抖音是视频优先的信息流平台，同时有搜索、个人主页和分享入口。抖音安全与信任中心公开的推荐系统说明包含：用户历史行为与内容特征参与召回；排序会预测用户对内容的交互行为；公开演示提到点赞、收藏、转发、评论等行为；系统还会考虑时间上下文，并使用多样性调节/重排。公开说明强调这是简化演示，不能据此推导具体权重或固定阈值。

**结论边界：** 抖音没有公开一套创作者可直接套用的“封面 CTR 权重表”。封面只是观看链路的一个入口；实际消费还取决于视频内容、开场、节奏、受众匹配、互动、负反馈和内容治理。

## 2. 抖音模式的设计任务

### 必须区分的三个画面

1. **视频上传封面**：在主页、搜索、分享或部分推荐入口中承担主题识别。
2. **视频首帧**：视频开始播放时用户看到的实际画面；不得假设它与上传封面必然相同。
3. **开场段**：视频最初的内容、动作、声音和信息承诺，负责把封面承诺转成真实观看体验。

用户只要求封面时，只制作上传封面；如果素材/任务包含视频首帧和开场优化，再分别给出，不把一张静态封面冒充首帧或完整视频方案。

### 封面策略优先级

- 主体/动作/结果一眼可辨：真人讲解、产品实测、屏幕操作、对比结果、真实现场。
- 单一观看理由：一个问题、一个反差、一个结果或一个动作，不堆多个卖点。
- 视觉锚点清楚：人脸表情、关键物体、真实 UI 结果或强场景关系至少有一个。
- 封面文案简洁，视频标题字段补充上下文；不要把完整标题、字幕和话题全部堆到图片上。
- 如果视频是操作教程，优先展示真实操作关键帧/结果帧，不制造假 UI、假运行状态或虚构“秒出结果”。

## 3. 标题与钩子

可根据内容选择：结果前置、问题/痛点、反常识、比较、具体步骤、身份圈定、真实经历、场景冲突。钩子只作为写作工具，不是平台验证过的固定公式。

- 封面主标题：短、具体、可在缩略图识别。
- 视频标题/描述：补充主题对象、适用场景和必要关键词；与视频内容一致。
- 话题：少而相关，避免无关热点蹭流量和关键词堆砌。
- 封面、标题、视频开场和正文必须兑现同一承诺。

## 4. 结构与视觉

优先考虑 L01 实拍主体、L07 前后对照、L08 产品主视觉、L09 真实 UI、L11 案例成果、L13 步骤路线、L17 视频关键帧。娱乐/剧情类按真实画面选择，不强行套知识卡片。

视觉表达可以更动态、更强动作，但不等于高饱和、大红大黄、密集大字。主体、动作趋势、结果或冲突关系要真实。需要人物时不伪造身份，不把 AI 合成角色冒充真实当事人。

## 5. 画幅与技术检查

- 视频画布通常按竖屏 9:16 规划；**视频画布比例不等于封面文件比例**。
- 抖音封面尺寸和显示裁切随发布入口、账号页面和客户端版本变化。默认先读取当前发布器/用户截图；若有本轮目标封面槽证据是3:4，才据此采用3:4（如1080×1440）；无此证据按用户指定或工作室默认9:16制作，平台预览保持NOT_RUN；若当前入口显示横版/其他比例，则按实际框形导出。
- 某个 GitHub Skill 的 1080×1440 默认值是该项目在特定抖音编辑器下的实践，不是全平台统一硬性规则。
- 标题、人脸、产品和关键 UI 留安全区；用实际主页/分享预览检查裁切，不把左下角或某固定区域永远认定为所有入口的统一遮挡区。

## 6. 商业内容与 AI 合规

- 商品/服务内容需保证封面、标题、视频和实际售卖对象一致；价格、效果、功效、客户评价和稀缺性必须有证据。
- 避免纯叫卖、搬运、套路化摆拍、低质重复和无依据专业背书。
- 使用 AI 生成的非真实音视频或可能造成公众混淆的内容，按抖音发布端要求主动显著标识；不得伪造真人、事件、实测或绕过 AI 标识。
- 任何平台 AI 标识以当前发布界面和官方规则为准；不得去除或伪造系统标识。

## 7. 发布后验证

使用创作者后台实际可用字段，优先检查：推荐/搜索来源、播放/有效播放、前段留存、平均播放时长、完播/播放进度、点赞、评论、分享、关注、负反馈、主页访问/转化（如后台提供）。

- 不假设所有账号/所有入口都能看到封面 CTR。
- 若开场留存差，先判断视频开场与封面承诺是否脱节；若封面点击相关指标低，才进一步检查封面锚点、标题和缩略图。
- 不把单条作品表现全部归因于封面；要考虑选题、受众、内容质量、发布时间和流量来源。
